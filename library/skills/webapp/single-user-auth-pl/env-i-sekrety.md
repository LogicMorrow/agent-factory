# Zmienne srodowiskowe i sekrety

## Wszystkie wymagane env vars

| Zmienna | Typ | Wymagana | Opis |
|---|---|---|---|
| `AUTH_SECRET` | string (≥32 bajty, hex lub base64) | TAK — BLOKER | Master sekret Auth.js v5 + klucz AES dla TOTP. Generuj `openssl rand -hex 32`. |
| `OWNER_USERNAME` | string | TAK — BLOKER | Login wlasciciela. Dowolny, sugerowany `wlasciciel`. Brak spacji. |
| `OWNER_PASSWORD_HASH` | string (Argon2id lub bcrypt) | TAK — BLOKER | Hash hasla. NIE plaintext. Generuj lokalnie `npm run generate-hash`. |
| `DATABASE_URL` | postgresql:// URL | TAK — BLOKER | Prisma connection string. |
| `OWNER_TOTP_SECRET` | AES-256-GCM ciphertext | Opcjonalna | Zaszyfrowany sekret TOTP. Zapisywany przez API settings/totp/enable — NIE recznie. |
| `REQUIRE_TOTP` | boolean string | Opcjonalna | `true` = wymusza TOTP dla wszystkich logikowan. Domyslnie `false`. |
| `NEXTAUTH_URL` | https:// URL | Produkcja | Pelny URL aplikacji. Wymagany dla callback URL Auth.js v5. |

## Zod schema walidacji env (fail fast)

```ts
// lib/env-validation.ts
import { z } from 'zod';

const envSchema = z.object({
  AUTH_SECRET: z
    .string
    .min(32, 'AUTH_SECRET musi miec minimum 32 znaki')
    .refine(
      (s) => /^[a-f0-9]{64}$|^[A-Za-z0-9+/]{43,}={0,2}$/.test(s),
      'AUTH_SECRET musi byc hex (64 znaki) lub base64 (≥43 znaki)'
    ),
  OWNER_USERNAME: z
    .string
    .min(1)
    .max(64)
    .regex(/^\S+$/, 'OWNER_USERNAME nie moze zawierac spacji'),
  OWNER_PASSWORD_HASH: z
    .string
    .refine(
      (h) => h.startsWith('$argon2') || h.startsWith('$2b') || h.startsWith('$2a'),
      'OWNER_PASSWORD_HASH musi byc hashem Argon2id ($argon2id$...) lub bcrypt ($2b$...)'
    ),
  DATABASE_URL: z.string.url('DATABASE_URL musi byc poprawnym URL'),
  REQUIRE_TOTP: z.enum(['true', 'false']).optional.default('false'),
  NEXTAUTH_URL: z
    .string
    .url
    .optional
    .refine(
      (url) => process.env.NODE_ENV !== 'production' || url !== undefined,
      'NEXTAUTH_URL wymagany w produkcji'
    ),
});

export function validateEnv: void {
  const result = envSchema.safeParse(process.env);
  if (!result.success) {
    console.error('BLAD KONFIGURACJI — niepoprawne zmienne srodowiskowe:');
    result.error.issues.forEach((issue) => {
      console.error(`  ${issue.path.join('.')}: ${issue.message}`);
    });
    process.exit(1);
  }
}

// Typ dla bezpiecznego dostepu do env
export type ValidatedEnv = z.infer<typeof envSchema>;
```

Walidacja wywolana w `auth.ts` przy inicjalizacji (zob. `flow-logowania.md`) — aplikacja nie startuje z brakujacymi/nieprawidlowymi secretami.

## Generowanie sekretow — komendy

### AUTH_SECRET (master secret)

```bash
openssl rand -hex 32
# Przyklad output: a3f2c1...64 znaki hex
# Wklej do .env jako: AUTH_SECRET=a3f2c1...
```

### OWNER_PASSWORD_HASH (hash hasla wlasciciela)

```bash
# Metoda 1 — przez skrypt projektu (po npm install)
npm run generate-hash -- --password=TwojeHasloTutaj

# Metoda 2 — node jednolinijkowy (wymaga @node-rs/argon2 zainstalowanego globalnie)
node -e "
const argon2 = require('@node-rs/argon2');
argon2.hash('TwojeHasloTutaj').then(h => console.log('OWNER_PASSWORD_HASH=' + h));
"

# Przyklad output:
# OWNER_PASSWORD_HASH=$argon2id$v=19$m=65536,t=3,p=4$abc123...$xyz789...
```

**Wymagania hasla (enforcement w generate-hash script):**
- Minimum 12 znakow
- Minimum 1 cyfra
- Minimum 1 znak specjalny
- Brak slabych wzorcow (password, 123456, qwerty itp.)

## Rotacja sekretow

### Rotacja AUTH_SECRET

Wymaga re-generowania sesji wszystkich uzytkownikow (jeden wlasciciel → wylogowanie i ponowne logowanie).

1. Wygeneruj nowy `AUTH_SECRET` (`openssl rand -hex 32`)
2. Zaktualizuj `.env` na serwerze
3. Restart aplikacji (`pm2 restart` / Docker compose down + up)
4. Wlasciciel loguje sie ponownie (stara sesja JWT nieodczytywalna)
5. Jesli TOTP wlaczone — `OWNER_TOTP_SECRET` jest zaszyfrowany tym samym kluczem. Musi byc re-encryptowany z nowym kluczem przed restartem lub TOTP musi byc wylaczone i ponownie wlaczone po restarcie.

### Rotacja hasla

```bash
npm run reset-password -- --password=NoweHaslo12!
# Generuje nowy hash, zapisuje do DB, loguje w audit_log
```

Pelny flow w `flow-logowania.md` sekcja "CLI reset hasla".

## Wzorzec secrets-handling (z `secrets-handling` skill)

Ten skill jest kompatybilny ze skill `secrets-handling`. Kluczowe zasady z tamtego skilla ktore tu obowiazuja:

- Nigdy env vars z wartosciami w repo (nawet encrypted) — tylko placeholders
- Rozrozniaj `.env` (lokalne, nie commitowane) od `.env.example` (commitowane, bez wartosci)
- Sekrety na produkcji przez: Docker secrets / Vault / zmienne env w systemie (nie plik .env na VPS jesli mozliwe)
- Rotacja sekretow jest planowanym zdarzeniem, nie awaryjnym — harmonogram co 6-12 miesiecy
